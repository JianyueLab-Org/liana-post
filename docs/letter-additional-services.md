# 信函与附加挂号服务

## 首版行为

- 新建信函产品代码为 U。`additionalServices: []` 生成 UU 开头的 S10 条码；`["REGISTRATION"]` 生成 RR 开头条码。
- 邮件持久化保存 U 产品与附加服务，详情接口返回服务列表。现有物流状态和轨迹事件不变。
- 旧 R 请求、旧 R 邮件保留“信函加挂号”语义；旧条码不重新生成。
- 收寄和报价页面共用附加服务标签控件。选择邮件产品后点击标签输入区域，勾选挂号，再点击完成。切换为不适用的产品会清除选项。
- 收寄提交先请求资费服务保存报价，成功后创建邮件，并展示报价明细。报价和邮件创建是两个请求，不是付款、结算或跨库事务；邮件创建失败可留下未使用的报价。重复点击收寄的幂等性仍属于后续订单工作。
- 申报价值不代表购买保价，不参与本次计价。

## 资费配置与兼容

全新环境的初始资费目录使用 U/C/E，U 规则内的 REGISTRATION 费用设置 `optional: true`。国内与国际挂号费沿用批准的 3.00 / 16.00，价格从数据库版本读取，无 Java 金额常量。管理员可在草稿中修改金额、勾选可选服务，发布新版本后生效。

已有发布版本不会被覆盖。对仅有 R 规则的历史版本，普通 U 信函沿用 R 规则基本资费，仅在选择挂号后计入 REGISTRATION；R 请求始终计入挂号。报价结果仍记录实际版本和实际规则标识。管理员复制旧版为草稿后，可把 R 产品改为 U，修改对应规则的 product 并将 REGISTRATION 设置为可选，再发布。

费用结构可表达固定的可选附加费，但首版仅允许信函挂号。保价还需要确认申报金额范围、费率、最低收费、赔偿与作废规则，再扩展计价算法及 OMS 服务校验，不能仅加一个标签就宣称支持保价。

## 数据库升级

已有 OMS 数据库先执行 `db_revise/20261014_letter_additional_services.sql`，再部署 OMS。此迁移仅添加 `mail.additional_services` 与 U 产品，不改历史记录。迁移在已有库只执行一次；全新 Docker 初始化会自动运行 db_revise 目录。直接使用 OMS resources/schema.sql 初始化的新库已含字段，不再执行该迁移。

## 验证

针对 OMS/资费的 Maven 测试覆盖产品条码、附加服务校验、普通与挂号价差、历史 R 兼容、报价快照、重量边界和资费版本。Vue 构建及前端测试验证接口与选项转换。支付、数码邮票核销和保价均不属于本次实现。
