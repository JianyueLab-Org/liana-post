## 固定场景与完成证据

| 场景 | 操作 | 必须保留的证据 |
|---|---|---|
| 正常首段、一个任务多路单 | 在 LN-OR-01 通过邮资收寄接口建立虚构邮件；建两个总包，等 OMS 装包确认，编两张路单；预告、封单、加入同班次任务、交接、出发/到达 | 两张完整封单版本、同任务分配、运力合计、交接和到达事实 |
| 部分/全部实收 | LN-OR-RC 只模拟扫描实际总包；固定接收请求提交并重试 | 每包唯一实收与双端 ACK，预期邮件仍未变为实收；响应重放时间/事件号相同 |
| 开拆重封 | LN-OR-RC 保留页面逐件模拟扫描；完成一次提交，等待 OMS 确认；路由并按格口重封 | 旧包 OPENED、新条码和逐件来源；dispatch 建包 ACK 与 OMS CONFIRMED 分开；新包可正常编批、封单 |
| 直封多段 | LN-OR-01 → LN-OR-RC → LN-NAM-AIR → LN-NAM-HQ，选择已配置 LAND/AIR/LAND 边 | 每段独立路单/任务；同包仅一条有效关系；旧事件重试不能覆盖新位置或任务 |
| 少包结束 | 到达后零包或部分实收，详情明确结束总包勾核 | 缺包分区和差异；无虚构包级接收、无邮件解绑；新接收被拒绝，旧请求可重放 |
| 缺件/盈余 | 在已收包中部分扫描，并手工模拟预期外邮件后完成 | 缺件保留原包归属，盈余隔离；两类差异均须管理员说明理由审核，不能伪装收到 |
| 路单关闭 | 实收包完成开拆确认或下一段勾核，差异全部审核，管理员申请关闭 | CLOSING → 两端匹配 ACK → CLOSED；缺袋分配 SETTLED、当前占用释放，物理实收数量不增加；运输任务可完成 |
| 下一段少包 | 已直封转运包在下一站未收，明确结束勾核 | 原位置 MISSING 并保留交出引用，发送地不能再次转运/开拆，未生成目的地实收 |
| 发前取消/改派 | 原任务发前取消，等 RELEASE 确认后重新分配原路单 | 历史不删；只有新分配有效；旧 ASSIGN/RELEASE 重放不改新占用 |
| 海运停航 | 对 LN-OR-02 / LN-SE-02 的已配置 SEA 连接模拟班次停用 | 无虚构陆运捷径；未出航不产生出发/到达 |
| 重试、乱序、并发 | 丢弃成功 HTTP 响应重试；同时结束勾核/接收、同时重封、关闭投递期间暂停一端 | 同键同内容返回原结果，异内容 409；无部分写入、双重当前占用或状态倒退；中断后固定命令继续投递 |
| 时区、权限与邮资回归 | 跨 UTC 12:00 对应业务日 +12；异机构操作；报价/核销/登录 | UTC 存储/+12 展示；异机构拒绝；原邮资与账户核心流程可用 |

## 闭环接口

- `POST /api/v1/sorting/manifests/{manifestNo}/finish-check`，正文 `{"requestNo":"CHECK-固定唯一请求","facilityCode":"LN-OR-RC"}`。只有接收机构或管理员可以结束勾核，运输必须已到达。
- `POST /api/v1/sorting/discrepancies/{verificationNo}/disposition`，管理员使用固定幂等键、匹配处置和 8—256 字依据；只处理 MANIFEST 差异，不处理 SECURITY 审核。
- `POST /api/v1/sorting/manifests/{manifestNo}/close`，同样提交固定请求号和目的机构，限管理员。
- `GET /api/v1/sorting/manifests/{manifestNo}/closure`，双方机构/管理员查询分区、固定命令和投递状态。网络失败保留原请求后重试，不生成新键碰运气。
- transport/dispatch 的内部 `/manifest-closures` 校验 `X-Manifest-Token`；只由 sorting outbox 调用。禁止人工伪造包级实收来解除占用。

每次验收记录环境项目名、端口、迁移版本、业务号、预期与实际结果。运行 `database/checks/invariants.sql` 所有计数须为零；同时检查旧演示容器及数据库未被切换。结构通过、H2 测试通过和页面构建均不能替代本表的 HTTP/浏览器与 InnoDB 场景验证。
